### PAGE: Index

**Purpose:** Adds navigation, search feedback, welcome messaging, and hero-button interactions to the landing page.

| JavaScript Feature | Actual Code/Method | Where Used | Purpose |

### PAGE: Login

**JavaScript File:** [login.js](frontend/login.js)

**Purpose:** Validates login form input, displays feedback, stores the entered email, and provides password visibility control.

| JavaScript Feature | Actual Code/Method | Where Used | Purpose |
|---|---|---|---|
| DOM selection | `document.querySelector()` | Form, email, password, toggle | Selects form controls |
| Form event | `addEventListener("submit")` | Login form | Handles login submission |
| Prevent submission | `event.preventDefault()` | Form handler | Prevents page reload |
| Conditions | `if`, `else if`, `else` | Validation | Checks email and password |
| String method | `trim()` | Email | Removes surrounding spaces |
| Regular expression | `/^[^\s@]+@[^\s@]+\.[^\s@]+$/` | Email | Performs basic email validation |
| DOM creation | `document.createElement("p")` | Validation feedback | Creates a message element |
| DOM update | `textContent` and `style.color` | Feedback message | Displays errors or success |
| Password toggle | `.type` | Password input | Switches between password and text |
| Storage | `localStorage.setItem()` | Successful login | Stores `loggedInUser` |

The login implementation validates format and length, but it does not compare the credentials against the registered `users` array. Any valid email and six-character password is accepted.

### PAGE: Signup

**JavaScript File:** [signup.js](frontend/signup.js)

**Purpose:** Validates registration fields, measures password strength, prevents duplicate emails, and stores user objects.

| JavaScript Feature | Actual Code/Method | Where Used | Purpose |
|---|---|---|---|
| DOM selection | `document.querySelector()` | Form fields | Selects registration controls |
| Input event | `addEventListener("input")` | Password field | Updates strength indicator |
| Submit event | `addEventListener("submit")` | Signup form | Handles registration |
| Conditions | `if`, `else if`, `else` | Validation | Checks all user inputs |
| String methods | `trim()`, `toLowerCase()` | Username and email | Normalizes input |
| Regular expression | Email regex | Email field | Checks email format |
| Password comparison | `password.value !== confirmPassword.value` | Confirmation | Detects mismatched passwords |
| Array reading | `JSON.parse()` | `users` storage | Loads existing users |
| Loop | `for...of` | Duplicate detection | Searches for an existing email |

Stored user structure:

```js
{
    username: name,
    email: address,
    password: password.value
}
```

Passwords are stored as plain text in browser storage. This is suitable only for an educational prototype.

## Part 11: Local Storage

| Storage Key | File | Data Stored | Purpose |
|---|---|---|---|
| `users` | signup.js | Array of user objects | Stores prototype registrations |
| `loggedInUser` | login.js, index.js | Email string | Stores and displays login identity |
| `selectedDeveloper` | Developers.js, DeveloperProfile.js | Developer object | Transfers selected profile |
| `connection:<name>` | DeveloperProfile.js | `"true"` | Persists connection state |
| `drafts` | writeBlog.js | Array of blog objects | Stores drafts |
| `publishedBlogs` | writeBlog.js | Array of blog objects | Stores published blogs |

Actual storage methods include:

```js
localStorage.getItem(...)
localStorage.setItem(...)
JSON.parse(...)
JSON.stringify(...)
```

`removeItem()` is not used.

> This is frontend/browser storage for the prototype and is not a replacement for secure backend authentication or database storage.

Important limitations:

- Login does not verify the `users` array.
- Passwords are stored in plain text.
- Published blogs are saved but not loaded into `BlogPage.js`.
- Project likes are not persisted.
- Malformed JSON in storage can cause `JSON.parse()` errors.

## Part 15: JavaScript Best Practices

| Best Practice | Evidence in Code | File | Purpose |
|---|---|---|---|
| Modular files | One script per page | All pages | Keeps page logic separated |
| `const` and `let` | Data and changing state | All files | Uses modern declarations |
| Meaningful names | `selectedDeveloper`, `passwordValue`, `published` | Multiple files | Improves readability |
| Functions | `render()`, `read()`, `showMessage()` | Several files | Groups reusable logic |
| Event listeners | `addEventListener()` | All files | Separates behavior from HTML |
| Strict equality | `===` | Multiple files | Avoids type coercion |
| Input validation | Form conditions and regex | Login, Signup, Write Blog | Handles invalid input |
| Safe empty storage reads | `getItem(...) || '[]'` | Signup and Write Blog | Handles missing storage |
| Fallback data | Default developer object | DeveloperProfile.js | Supports direct page access |
| JSON serialization | `JSON.stringify()` and `JSON.parse()` | Storage features | Stores structured objects |
| DOM-only feedback | `textContent` messages | Forms and profile | Avoids excessive alerts |
| Iteration | `forEach()`, `map()`, `for...of` | Dynamic pages | Handles collections |

### Improvements or Violations

- Login accepts any valid email/password combination and does not authenticate against registered users.
- Passwords are stored in plain text.
- `JSON.parse()` is not protected with `try...catch`.
- User-entered content is inserted using `innerHTML`, which could create an injection risk in a real application.
- Project likes are not stored in localStorage.
- Published blogs are not displayed on the blog page.
- Pagination controls are visible but have no JavaScript behavior.
- The featured image is not processed.
- The original word counter is not updated.
- The code contains very long single-line functions in several scripts, which reduces readability.
- `window.alert()` is used for project submission rather than a DOM message.

## Part 16: Report-Ready Summary

### JavaScript Implementation Summary

DevSphere uses JavaScript to convert the Phase 1 static HTML and CSS website into an interactive frontend application. Each page has a separate JavaScript file, allowing page-specific functionality to remain modular and understandable.

JavaScript adds navigation, form validation, password visibility controls, dynamic search, category filtering, project sorting, project likes, blog previews, draft storage, publishing, developer profile selection, animated statistics, and Chart.js data visualization.

The DOM is manipulated using methods such as `querySelector()`, `querySelectorAll()`, `createElement()`, `innerHTML`, `textContent`, and `appendChild()`. Arrays and objects represent users, blogs, developers, projects, skills, and statistics.

Browser events such as `click`, `input`, `submit`, `change`, `scroll`, and `DOMContentLoaded` connect user actions to application behavior. Window APIs provide navigation, timers, scrolling information, alerts, and localStorage access.

The project uses localStorage as temporary browser storage for users, login identity, selected developers, connections, drafts, and published blogs. Chart.js is used on the developer profile page to display project, blog, and connection statistics.
