1. PROJECT ARCHITECTURE
================================================================================

DevSphere implements a Dual-Layer React Architecture centered around a Vite 
Multi-Page Application (MPA) with Progressive Enhancement React Islands, coexisting 
with a modular React Single-Page Application (SPA) component system:

1. Primary Architecture: Progressive Enhancement React Islands (Vite MPA)
   - Host Documents: 9 semantic HTML files located in `frontend/` (`index.html`, 
     `login.html`, `signup.html`, `BlogPage.html`, `writeBlog.html`, `Developers.html`, 
     `DeveloperProfile.html`, `Projects.html`, `About.html`).
   - Entry Point Configuration: `vite.config.js` defines Rollup inputs for all 9 
     HTML documents under `build.rollupOptions.input`.
   - Island Mounting: Each HTML document contains an isolated mounting container 
     (e.g., `#blog-island-root`, `#profile-interactive-root`) loaded via ES module 
     scripts (`<script type="module" src="/src/islands/..."></script>`).
   - Coexistence Principle: The existing semantic HTML document structure, native 
     CSS stylesheets, and Vanilla JavaScript logic remain active. React islands 
     mount strictly into targeted high-interaction subtrees (search, filtering, 
     controlled forms, interactive charts, and live counters). Vanilla scripts 
     include guard clauses (`if (document.getElementById('...-root')) return;`) to 
     yield DOM ownership to React without conflict.

2. Secondary Architecture: Modular React Component & SPA System
   - Host Document: Root `index.html` mounting into `<div id="root"></div>` via 
     `src/main.jsx`.
   - Component Tree: `src/main.jsx` renders `<DevSphereProvider>` and `<App />`. 
     `src/App.jsx` utilizes `react-router-dom` (`BrowserRouter`, `Routes`, `Route`) 
     to provide client-side routing across 9 route paths (`/`, `/login`, `/signup`, 
     `/blogs`, `/write-blog`, `/developers`, `/developer-profile`, `/projects`, 
     `/about`).
   - Reusable Component Library: Located in `src/components/` (subdivided into 
     `cards/`, `charts/`, `layout/`, and `ui/`), consumed by full-page React 
     components in `src/pages/`.
   - Shared State & Utilities: Managed through `src/context/DevSphereContext.jsx`, 
     custom hooks in `src/hooks/` (`useAuth`, `useLocalStorage`, `useSearch`), and 
     centralized active datasets in `src/data/`.

Both layers share identical data structures (`src/data/`), identical custom hooks 
(`src/hooks/`), and identical localStorage schemas, ensuring 100% interoperability.

7. COMPLETE CUSTOM HOOK INVENTORY
================================================================================

The codebase contains 3 production-grade custom hooks:

1. Hook Name: useLocalStorage
   - File Path: src/hooks/useLocalStorage.js
   - Purpose: Dual-compatible localStorage persistence. Reads JSON-serialized 
     structures (arrays, objects) but gracefully falls back to raw strings (preventing 
     SyntaxError crashes on legacy 'loggedInUser' written by Vanilla JS).
   - Built-in Hooks Used: useState, useEffect, useDebugValue
   - useDebugValue: `useDebugValue(`${key}: ${...}`)` displays key type, array count, 
     or ready state in React DevTools.
   - Consumed By: BlogIsland, WriteBlogIsland, DevelopersIsland, Signup, WriteBlog, 
     DeveloperProfile, DevSphereContext.

2. Hook Name: useSearch
   - File Path: src/hooks/useSearch.js
   - Purpose: Encapsulates search query state, text extraction, and memoized result 
     filtering across item collections.
   - Built-in Hooks Used: useState, useMemo, useDebugValue
   - useDebugValue: `useDebugValue(`Query: "${query}" | Results: ${results.length}`)` 
     exposes search diagnostics to DevTools.
   - Consumed By: Developers (SPA).

3. Hook Name: useAuth
   - File Path: src/hooks/useAuth.js
   - Purpose: Encapsulates authentication session operations (login, logout, active 
     user identification) by interfacing directly with DevSphereContext.
   - Built-in Hooks Used: useDebugValue (accesses useContext inside useDevSphere)
   - useDebugValue: `useDebugValue(isAuthenticated ? `User: ${currentUser}` : "Guest")` 
     safely exposes session state without leaking sensitive passwords.
   - Consumed By: Home, Login, WriteBlog, Navbar, LoginForm Island.

10. REACT ARCHITECTURE SUMMARY
================================================================================

- Progressive Enhancement Islands: 9 dedicated islands in `src/islands/` auto-mount 
  to specific DOM elements when their respective host HTML page loads. They 
  manage high-value interaction zones without displacing semantic HTML document 
  landmarks.
- Coexistence with Vanilla JS: Legacy scripts in `frontend/*.js` check for the 
  presence of island root containers and exit early. Vanilla JS code handles 
  non-React document areas; React controls its own DOM subtrees.
- Direct CSS Class Reuse: React components apply classes from `frontend/*.css` 
  (`.blogCard`, `.card`, `.grid`, `.pic`, `.btn`, etc.) directly, eliminating the 
  need for duplicate stylesheets or heavy CSS-in-JS frameworks.
- LocalStorage Compatibility: The custom `useLocalStorage` hook transparently 
  handles both raw string storage (legacy `loggedInUser`) and structured JSON data 
  (`users`, `publishedBlogs`, `selectedDeveloper`), preventing runtime parse errors.
- Chart Lifecycle Integrity: Chart.js instances are tracked via `useRef` and 
  explicitly destroyed via `.destroy()` in `useEffect` cleanup callbacks, preventing 
  canvas reuse errors and memory leaks.

12. REPORT-READY SUMMARY

A. Pages Analyzed:
   9 distinct pages (Home, Login, Signup, Blogs, Write Blog, Developers, 
   Developer Profile, Projects, About) across both Progressive Enhancement 
   Island architecture and React SPA architecture.

B. Total React Components:
   23 discrete React components (9 React Islands, 9 Full Page Components, 
   1 Application Root, 1 Context Provider, 13 Reusable UI/Card/Layout Components).

C. Total Custom Hooks:
   3 production custom hooks: `useLocalStorage`, `useSearch`, `useAuth`.

D. Built-in Hooks Used:
   `useState`, `useEffect`, `useContext`, `useMemo`, `useRef`, `useDebugValue`.

E. Routing Approach:
   Vite Multi-Page Application (MPA) architecture for progressive enhancement 
   with native HTML entry points, complemented by a client-side React Router 
   v6 (`BrowserRouter`) implementation for SPA exploration.

F. State Management Approach:
   Component-level reactive state via `useState` and `useMemo`, combined with 
   React Context (`DevSphereContext`) for authentication session state and 
   synchronized `localStorage` for cross-page persistence.

G. Form Handling Approach:
   Controlled components with two-way state binding (`value` and `onChange`), 
   real-time input constraints (e.g. 5000 character limit), regex email validation, 
   real-time password strength indicators, and programmatic error focus.

H. Ref Usage:
   `useRef` is employed for canvas element targeting (`ProfileChart`, `ActivityChart`), 
   input focus management on validation errors (`LoginForm`), textarea focus on 
   preview toggle (`WriteBlogIsland`), and keyboard escape blur (`SearchBar`). 
   `forwardRef` is implemented in `FormInput`.

I. Context Usage:
   `DevSphereContext` provides global authentication status (`currentUser`, 
   `isAuthenticated`, `login`, `logout`) without prop drilling.

J. Memoization Usage:
   `useMemo` optimizes search query evaluation, multi-criteria category filtering, 
   and array sorting across `BlogIsland`, `ProjectsIsland`, `DevelopersIsland`, 
   and `useSearch`.

K. External Libraries:
   `chart.js` (^4.4.8) for interactive canvas activity charts; `react-router-dom` 
   (^6.28.0) for client-side routing.

L. Progressive Enhancement / MPA Integration:
   React islands mount directly into designated container IDs in `frontend/*.html` 
   while preserving the underlying HTML5 document structure, CSS3 styling rules, 
   and legacy Vanilla JavaScript files through coexistence guards.

M. Important Implementation Limitations:
   Authentication is prototype-level (credentials stored in localStorage without 
   backend password hashing); blog publishing and project likes are stored in the 
   browser without cross-device database synchronization.
